# L0 선언 판정 기준 (SSOT)

> 이 파일은 semantic_judge_gate.py의 판정 기준 데이터다.
> 판정자(claude CLI)에게 이 파일 전문을 프롬프트로 전달한다.
> 판정자는 이 기준만으로 PASS/FAIL을 결정한다 — 자체 학습 지식으로 완화 금지.

---

## 합격 기준

L0 선언이 PASS이려면 다음 세 조건을 모두 충족해야 한다.

### 조건 A — 비즈니스/존재 목적 서술
"이것이 없으면 무엇이 실패하는가"에 답한다.
사용자·조직·프로세스 관점에서 최종적으로 발생하는 결과를 서술한다.

- PASS 예시 1: "고객이 견적을 사람 도움 없이 스스로 완성할 수 없다"
- PASS 예시 2: "운영팀이 배포 실패를 30분 이내에 탐지하지 못한다"
- FAIL 예시 1: "타임아웃 10초 이내 완료" ← 기술 수치가 목적 자리를 차지함
- FAIL 예시 2: "JSON 파싱 기능 구현" ← 구현 행위가 목적 자리를 차지함

### 조건 B — 구현 수단·도구·수치 비종속
L0는 특정 언어, 라이브러리, 알고리즘, 시간 수치, 퍼센트, 파일명에 언급이 없어야 한다.
L0를 달성하는 방법이 달라져도 L0 자체는 변하지 않아야 한다.

- PASS 예시 1: "신규 입사자가 첫날부터 개발 환경을 스스로 구성한다"
- PASS 예시 2: "팀원이 코드 변경 이력을 언제든 추적할 수 있다"
- FAIL 예시 1: "Python subprocess로 외부 API를 60초 안에 호출" ← 도구+수치가 목적
- FAIL 예시 2: "Redis 캐싱으로 응답속도 향상" ← 기술 수단이 목적 자리

### 조건 C — 상위 목적에 귀속 가능
한 단계 위의 목적이 존재할 수 있어야 한다 (최상위 L0이 아닌 경우).
동어반복("이 파일의 목적은 이 파일을 위한 것")이면 FAIL.
빈 껍데기("중요한 기능", "핵심 로직")이면 FAIL.

- PASS 예시 1: "리뷰어가 PR 맥락을 코드 없이 이해한다" ← 팀 협업 품질이라는 상위 목적에 귀속 가능
- PASS 예시 2: "사용자가 오류 메시지를 보고 스스로 문제를 해결한다" ← 사용자 자립이라는 상위 목적에 귀속 가능
- FAIL 예시 1: "이 모듈의 목적은 이 모듈을 동작시키는 것" ← 동어반복
- FAIL 예시 2: "중요한 기능을 담당한다" ← 내용 없는 껍데기

---

## 불합격 즉시 판정 (하나라도 해당하면 FAIL)

1. 기술 파라미터·수치·도구명·언어명이 선언의 핵심 의미를 구성함
2. "~의 목적은 ~이다" 형식이지만 앞뒤가 동일한 개념의 반복
3. "중요", "핵심", "필수", "기능", "로직" 등 내용 없는 수식어만으로 구성
4. 선언이 사실상 비어 있음 (빈 문자열, 공백, "TODO", "미정")
5. 선언이 L1/L2/L3 수준임 — 예: 구체적 구현 방법·설계 결정·코드 구조 서술

---

## 판정 응답 형식

반드시 JSON 배열만 응답. 앞뒤 설명 텍스트 금지. 코드펜스(```) 허용.

```json
[
  {"line": "# L0: <원문>", "verdict": "PASS", "reason": "<한 줄 근거>"},
  {"line": "# L0: <원문>", "verdict": "FAIL", "reason": "<구체적 위반 조건 + 재작성 방향>"}
]
```
