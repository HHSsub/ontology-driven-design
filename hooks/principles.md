# principles.md — 강제 불가 원칙 저장소

> violation_registry.json의 기계 검증 대상에서 제외된 원칙들.
> 씨앗(l0_seeds) 중 규칙(열매)이 없는 것, 또는 L1 구조 서술 불가 원칙.
> 훅으로 차단할 수 없지만 모든 판단의 준거점이 된다.

---

## 씨앗: reader_context

**원칙**: 모든 출력은 수신자의 기호체계로 구성된다.

발신자(LLM 포함)가 아는 것 ≠ 수신자가 아는 것.
수신자가 원본 제공자(유저)일 때, 그 정보의 SSOT는 수신자가 직접 제공한 텍스트뿐이다.
LLM 추론으로 보완하는 것 = 발신자 기호체계로 수신자 기호체계를 대체하는 것.

**왜 기계 강제 불가**: 출력 내용의 "기호체계 적합성"은 정규식으로 판단할 수 없다.

**적용 조건**: 유저가 제공하지 않은 정보로 빈칸을 채우려 할 때.
프로젝트 설명, 도메인 컨텐츠, UI 카피 — 임의 생성 전 질문 먼저.

---

## 씨앗: enforcement_structure

**원칙**: 씨앗은 판단 공간, 가지는 도메인 분화, 규칙은 기계 강제.

이 계층을 혼동하면:
- 씨앗 수준 원칙을 규칙으로 표현 → L3 패치 무한 증식
- 모든 케이스를 열거하려 함 → 누락된 케이스 = 영구 구멍
- 규칙 수 증가 = 진화 실패 신호 (성공하면 규칙이 줄어야 한다)

**판단 질문**: "이 조건은 이 케이스 없이도 성립하는가?"
- YES → L1 구조 (규칙으로 표현 가능)
- NO, 이 케이스가 있어야만 성립 → L3 하드코딩 (금지)

**적용 조건**: ontology-learning Phase 6에서 새 규칙 추가 여부 판단 시.

---

## 씨앗: self_limiting_evolution

**원칙**: 진화는 누적이 아니라 깊이다.

새 실수 발생 시 순서:
1. 기존 씨앗·가지가 이미 커버했어야 했는가? → YES면 심화
2. 기존 씨앗으로 표현 불가한 새 L0 영역인가? → YES면 씨앗 추가 (극히 드물어야 함)
3. 케이스 나열·키워드 목록·경로 하드코딩 → 모두 L3 패치, 금지

**성숙 신호** (violation_stats.json에서 측정):
- rules 총 개수가 시간이 지날수록 감소 → 내재화 진행 중
- trigger_count > 0 후 > 30일 침묵 → 행동에 내재화됨, 삭제 후보
- trigger_count = 0 후 > 14일 → 과잉 명시, L0 재추상화 검토

**적용 조건**: ontology-learning 후 violation_registry.json 변경 여부 결정 시.

---

## 전역 원칙: 비가역 행동 사전 보고

L0 선언 없이 비가역 행동 금지:
- 파일 삭제, DB 변경, 배포, 이메일 발송 전 → L0 연결 확인 필수
- "이 행동이 어떤 L0를 달성하는가?" → 답 없으면 STOP
- 되돌릴 수 없는 행동은 유저에게 정확한 영향력 설명 후 허락받기 필수

**왜 기계 강제 불가**: 비가역성은 행동 유형마다 다르며, 문맥에 따라 달라진다.

---

## 전역 원칙: scope-channel match — 학습의 저장 채널은 적용 범위와 일치해야 한다

원칙이 적용되는 범위와 그것이 로드되는 범위가 다르면 학습은 구조적으로 망각된다:
- 전역 행동 원칙(OS·도구·쉘·AI 일반) → 전역 CLAUDE.md (모든 세션이 로드하는 유일한 텍스트 채널)
- 전역-도메인 원칙 → violation_registry.json 가지 / 이 파일
- 프로젝트 종속 원칙 → 그 프로젝트의 memory 디렉토리

게이트 차단은 세션 내 피해 방지이지 세션 간 학습 채널이 아니다 — 세션은 stateless다.
교차 신호: violation_stats.json에서 같은 규칙이 여러 프로젝트에서 발동 = 그 원칙은 전역 범위.

**왜 기계 강제 불가**: "이 원칙이 프로젝트 없이도 성립하는가"는 의미 판단이다. 정규식 분류 불가.

**적용 조건**: ontology-learning Phase 5-0에서 저장 위치 결정 시.

(실측 근거: 도구 선택 원칙이 프로젝트 silo 메모리에만 저장 → 타 프로젝트에서 2일간 40회 재위반, 2026-06-11)

## 전역 원칙: 외부 진실 우선

유저가 "안 됐다", "아직 있다"고 하면:
내부 분석을 취소하고 외부 환경을 먼저 재확인.

코드 분석 = 내부 가설.
유저의 관찰 결과 = 외부 진실.

**왜 기계 강제 불가**: 유저 발화의 의미는 정규식으로 분류할 수 없다.

---

## 규칙 생명주기 (이 파일로 이동 조건)

violation_registry.json의 l1_branches 중:
- trigger_count = 0 AND added > 14일 → 과잉 명시 의심. principles.md로 이동 검토.
- 대응하는 fruit_rule이 규칙으로 표현 불가한 것 → 이 파일로 이동 필수.

이 파일에 옮겨진 원칙은 삭제가 아니다.
기계 강제에서 인간 판단으로 책임이 이동한 것이다.
