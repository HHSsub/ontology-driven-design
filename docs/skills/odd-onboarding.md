# odd-onboarding

구현 전에 프로젝트/기능의 존재 목적을 확정합니다.

슬래시 커맨드: `/odd-onboarding`

---

## 언제 사용하나

- 새 프로젝트를 시작하기 전
- 새 기능을 추가하기 전
- 방향이 불명확한 상태에서 구현을 시작하려 할 때

## 무엇을 하나

전문용어 없이 5개 영역의 자연어 질문을 통해 L0-L3 온톨로지를 확정합니다.
결과물로 `ONBOARDING.md`가 생성됩니다 — 이것이 프로젝트의 헌법이 됩니다.

### 5개 질문 영역

| 영역 | 묻는 것 | 결과 |
|------|---------|------|
| **존재 목적** | 없으면 어떤 불편함? 잘 됐다는 걸 어떻게 아나? | L0 확정 |
| **절대 금지** | 이 도구가 오히려 방해가 되는 상황은? | Never-Do 확정 |
| **자동 vs 컨트롤** | 자동으로 해줬으면 하는 것 vs 직접 하고 싶은 것 | L1 구조 확정 |
| **트레이드오프** | 간단함 vs 정확함, 마찰 수용 수준 | L2 판단 기준 확정 |
| **AI 자율 범위** | AI가 알아서 해도 되는 것 vs 반드시 확인해야 하는 것 | 자율성 경계 확정 |

## 절대 금지 (스킬 내부)

- 기술 스택, 언어, 프레임워크 얘기 ❌
- AWS, API, 비동기 같은 전문용어 사용 ❌
- 구현 방법 제안 ❌ — 오직 "무엇"과 "왜"만 확정

## 출력물

```markdown
# ONBOARDING — [프로젝트명]

## L0: 존재 목적
[한 문장 — 어떤 상태가 되는 것이 목표인가]

## 성공 기준
## 실패 기준
## Never-Do
## L1: 전체 흐름
## 자동 vs 직접 컨트롤
## L2: 핵심 트레이드오프 결정
## AI 자율 판단 범위
## 이 문서에서 파생되는 구현 원칙
```
