# Pyramid Thinking — The Philosophy Behind ODD

ODD implements **Pyramid Thinking (피라미드사고법)** in Claude Code.

## Overcoming Entropy

The tragedy of the information age is not a lack of knowledge, but an excess of horizontal information (How-to, Data) that has pushed entropy to its limits.

Pyramid Thinking organizes this fragmented horizontal knowledge into a 4-layer vertical hierarchy using the philosophical concept of Ontology — building the **'skeleton of intelligence'**.

## Soul and Body Must Unite

This hierarchy does not mean upper layers are superior to lower ones.

If upper layers (L0~L1) are the **'Soul'** pointing direction, lower layers (L2~L3) are the **'Body'** that makes it work in reality. An upper hierarchy without execution power is empty fantasy; a lower hierarchy without essence is blind labor.

## The 4 Layers of Existence

### [L0] Ontology / Purpose — "Ultimate Integration and Internalization"
The deepest purpose for which this system exists.

### [L1] Abstract / Structure — "Architecture of Order"
The macroscopic blueprint for bringing L0's philosophy into reality.

### [L2] Logic / Process — "Compromise and Choice with Reality"
Decision-making logic that resolves contradictions when applying L1 to reality.

### [L3] Execution / Instance — "The Physical Anchor"
Code, tools, rules, physical actions. Without this solid foundation, L0's ideals cannot advance a single step.

## Application in AI

AI coding agents execute L3 (implementation) brilliantly while losing track of L0 (purpose). ODD solves this by:

1. Forcing purpose declaration before every action
2. Detecting existence-clinging (hardcoding that becomes lies over time)
3. Auditing that every function traces back to business goals
4. Requiring ontology review before implementation

## Not patterns but agents — enforce meaning with meaning

ODD's enforcement layer splits in two. Confusing the two turns the whole of governance into decoration.

**Fixed-pattern violations** (shell syntax, filename rules, banned keywords) are caught by regex — instant, free, deterministic. Here, patterns are the right tool.

**Meaning violations** are different. "Did this L0 disguise an implementation means as a purpose?", "Did it change existing code without analyzing the premise?", "Did it declare completion without external verification?" — these judgments have infinite expressions. Regex won't catch ten of ten million cases. Endlessly stacking cases into a regex file is accumulation, not evolution, and is permanently breached by every new expression.

**Hence ODD's invariant principle: semantic judgment, triggering, and learning are never faked with patterns — they are always done by an agent (LLM judge).** Meaning must be caught by meaning. `semantic_judge_gate` is the implementation of this principle — it delegates the truth of an L0 declaration to an independent agent. Pattern hooks for genuinely mechanical violations only; everything that requires judgment goes to an agent.
