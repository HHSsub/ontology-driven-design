# Pyramid Ontology — 피라미드 위계 온톨로지

## L0: 이 스킬의 목적

**어떤 산출물이든 최종 목적(L0)에 연결되지 않은 행동은 금지다.**
연결 확인 없이 만들어진 것은 쓰레기다. 기능이 동작해도 목적이 없으면 실패다.

---

## 강제 법칙 — 모든 작업 시작 전 반드시 선언

```
L0: [이 작업이 달성해야 할 비즈니스/사용자 최종 목적]
L1: [이 작업의 시스템/문서 목표 — L0를 달성하는 경로]
L2: [지금 구현/작성하는 기능 단위 — L1을 구성하는 조각]
```

**L0를 말할 수 없으면 → 방향이 잘못된 것이다. 작업 중단. 먼저 물어라.**

---

## 위계 정의

| 레벨 | 층위 | 본질 | 예시 |
|------|------|------|------|
| **L0** | 존재론 / 목적 | **궁극적 융합과 내재화** — "목표가 무엇인가"가 아니라 "왜 이것이 존재해야 하는가". 수단이 외부 도구로 남는 것을 넘어 인간·시스템에 완전히 내재화되는 상태 | (코드) 창작자가 배포를 의식하지 않아도 되는 상태가 된다 / (문서) 투자자가 수치를 이해하는 것을 넘어 방향성에 진심으로 동의한다 |
| **L1** | 추상 / 구조 | **질서의 아키텍처** — L0의 철학을 현실로 끌어내리는 불변의 설계도. 모든 하위 행동이 이 궤도를 벗어나지 않도록 통제하는 중력장 | (코드) 영상생성 → 편집 → 업로드 자동화 파이프라인 전체 / (문서) 현황 → 문제 → 대안 → 권고의 피라미드 논증 구조 |
| **L2** | 로직 / 트레이드오프 | **현실과의 타협과 선택** — 구조(L1)를 현실에 적용할 때 발생하는 모순을 해결하는 의사결정 기록. 모든 선택에는 기회비용이 따른다 | (코드) 폴링 방식 선택: 실시간성 포기 대신 비용 절감 / (문서) 도표 단순화: 정확도 일부 희생, 직관성 확보 |
| **L3** | 실행 / 인스턴스 | **물리적 닻** — 가장 구체적인 실체. L3가 작동하지 않으면 L0의 이상은 한 발짝도 나아갈 수 없다 | (코드) Kling API 폴링 구현, ffmpeg concat 실행, 에러 로그 파싱 / (문서) 특정 차트 선택, 수치 포맷 결정, 문장 교정 |

**도메인 무관 — 코드든 보고서든 PPT든 이메일이든 동일하게 적용된다.**

> L2는 기능 분해(feature decomposition)가 아니다. 구조가 현실과 충돌할 때 어떤 선택을 했고 그 기회비용은 무엇인지를 기록하는 층위다.

## 비가역 행동 강제 가드

파일 삭제 / 배포 / 외부 API 호출 / DB 변경 / 이메일 발송 전:

1. **"이 행동이 어떤 L0를 달성하는가?"** → 답 없으면 STOP
2. **"이 행동이 L0 미달 상태(실패/진행중)인 항목에 영향을 주는가?"** → 예이면 STOP
3. **"이 행동은 되돌릴 수 있는가?"** → 아니오이면 L0 연결 확인 필수

## SSOT (단일 진실 원칙) — 열거형 개념 모음의 법칙

**어떤 개념 집합이든 단 하나의 소스(SSOT)에서 존재해야 한다.**
같은 개념 집합이 N개 독립 위치에 수동으로 유지되는 순간 온톨로지 의존성 체인이 파괴된다.

**강제 절차 (열거형 개념 모음 수정 전)**:
1. grep/검색으로 해당 개념에 의존하는 모든 파생 표현 먼저 탐색
2. 파생 표현은 함수로 자동 생성하거나 SSOT 변경과 동시에 전부 갱신
3. 탐색 없이 수정 = 의존성 체인 파괴 = SSOT 위반

"열거형 개념 모음" = 코드의 리스트·레지스트리·enum·딕셔너리, 문서의 목록·섹션·분류 — 어떤 형태든

## Red Flags — 이 생각이 들면 즉시 멈춰라

| 생각 | 실제 의미 | 조치 |
|------|---------|------|
| "L2/L3 구현부터 하고 L0 연결은 나중에" | L0 달성 포기 선언 | 중단 — L0 먼저 |
| "일단 완성하고 업로드는 다음 단계에" | terminal 상태 = L0 미달 | 중단 — 파이프라인 끝까지 |
| "이 함수의 목적? 그냥 도움이 되려고" | L레벨 불명 = 방향 없음 | 재설계 |
| "삭제해도 괜찮겠지" | L0 기여도 미확인 | 확인 먼저 |
| "요청대로 만들면 됨" | L0 연결 미검증 | 연결 확인 먼저 |
| "지금 하는 건 작은 거니까" | 모든 행동은 L0에 귀속 | 선언 먼저 |
| "A만 바꾸면 됨" | A에 의존하는 B,C,D 갱신 안 함 | grep으로 파생 확인 먼저 |
| "나중에 help도 고치지 뭐" | SSOT 의존성 체인 파괴 | 동시에 갱신하거나 파생 함수화 먼저 |

## 모든 산출물에 적용되는 법칙

- **모든 파일은 첫 줄에 L0 선언이 있어야 한다.** 형식은 자유:
  - `# L0: ...` (Python/YAML/Shell)
  - `// L0: ...` (JS/TS/Go/Java)
  - `<!-- L0: ... -->` (HTML/XML)
  - `L0: ...` (Markdown/문서 첫 줄)
- **파이프라인·자동화 작업 단위는 반드시 L0까지 완주한다.** 중간 완성은 완료가 아니다.
- L0 달성 전 중단되면 → 반드시 재시도/resume 경로가 있어야 함

