# /odd-onboarding — 온톨로지 온보딩

L0: 구현 전에 방향을 확정하여 방향 오류를 사전에 제거한다
L1: 자연어 질문 → 답변 수집 → L0-L3 온톨로지 문서 생성 → 구현 원칙 확정
L2: 5개 영역 질문 → AskUserQuestion 인터랙션 → ONBOARDING.md 출력

---

## 이 스킬의 목적

프로그램을 만들기 전에 "왜"와 "무엇을 절대 하면 안 되는가"를 확정한다.

나중에 "이게 아니었어"라고 깨닫는 상황을 없애는 것이 이 스킬의 전부다.

**절대 금지 (이 스킬 내에서)**:
- 기술 스택, 프레임워크, 언어 얘기는 이 단계에서 꺼내지 않는다
- 전문용어로 묻지 않는다 (AWS, API, 비동기 같은 용어 금지)
- 구현 방법 제안 금지 — 오직 "무엇"과 "왜"만 확정한다
- 사용자가 아직 생각 안 한 부분을 강요하지 않는다

---

## 실행 절차

### Step 0 — 컨텍스트 파악

인자가 있으면 해당 프로젝트/기능에 대해 온보딩.
없으면 현재 워킹 디렉토리 기준.

### Step 1 — 5개 영역 질문 (AskUserQuestion으로)

아래 5개 영역을 **평이한 자연어**로 물어본다.
한 번에 최대 4개 질문. 영역 당 핵심 1개 질문만.

---

#### 영역 1: 존재 목적 (L0)

**묻는 것**: 이 프로젝트/기능이 없으면 어떤 불편함이 있나요?
→ "잘 됐다"는 걸 어떻게 알 수 있나요?
→ 실패하면 어떤 상황이 됩니까?

핵심: **어떤 상태가 되는 것**이 목표인가? (행동이나 기능이 아니라)

---

#### 영역 2: 절대 하지 말아야 할 것 (Never-Do)

**묻는 것**: 이 도구가 오히려 방해가 되는 상황은 어떤 건가요?
→ "이런 식으로 동작하면 절대 안 된다"는 게 있나요?
→ 지금까지 비슷한 것을 써봤다면, 가장 불편했던 점은?

핵심: **L0를 훼손하는 행동**을 먼저 막는다.

---

#### 영역 3: 자동 vs 직접 컨트롤 (L1 구조)

**묻는 것**: 자동으로 다 해줬으면 하는 것 vs 직접 컨트롤하고 싶은 것은?
→ 이 도구를 주로 언제, 어떤 상황에서 씁니까? (이동 중, 아침에, 급하게 등)
→ 하루에 몇 번 정도 상호작용할 것 같나요?

핵심: **사람의 개입이 필요한 영역**과 **완전 자동 영역**을 분리한다.

---

#### 영역 4: 트레이드오프 판단 (L2)

**묻는 것**: 간단하고 빠른 것 vs 정확하고 상세한 것 중 더 중요한 것은?
→ 이 도구가 당신한테 더 많이 물어봐도 괜찮은가요, 아니면 알아서 판단해줬으면 하나요?
→ 입력하는 게 귀찮더라도 결과가 더 좋으면 괜찮나요, 아니면 입력을 최소화하길 원하나요?

핵심: **얼마나 많은 마찰을 수용할 것인가** 결정한다.

---

#### 영역 5: AI 자율 판단 범위 (L2-L3 경계)

**묻는 것**: AI가 알아서 결정해도 되는 것은? 반드시 물어봐야 하는 것은?
→ 틀려도 괜찮은 것 vs 반드시 맞아야 하는 것은?
→ 어떤 것은 내가 최종 승인을 해야 하나요?

핵심: **에이전트의 자율성 경계**를 명시한다.

---

### Step 2 — 온톨로지 문서 생성

답변을 바탕으로 `ONBOARDING.md` 생성:

```markdown
# ONBOARDING — [프로젝트명]
생성일: [YYYY-MM-DD]

## L0: 존재 목적
[한 문장으로 — 어떤 상태가 되는 것이 목표인가]

## 성공 기준
- [잘 됐다는 걸 알 수 있는 구체적 조건들]

## 실패 기준
- [실패했다는 걸 알 수 있는 조건들]

## Never-Do (절대 금지)
- [이 L0를 훼손하는 행동 목록]

## L1: 전체 흐름
[사용자의 하루 흐름에서 이 도구가 어떻게 통합되는가]

## 자동 vs 직접 컨트롤
- 자동 (AI 독립 판단): [영역 목록]
- 직접 컨트롤 필요: [영역 목록]
- 최종 승인 필요: [영역 목록]

## L2: 핵심 트레이드오프 결정
| 선택 | 결정 | 이유 |
|------|------|------|
| 간단 vs 상세 | [결정] | [이유] |
| 자동 vs 수동 | [결정] | [이유] |
| 마찰 수용 수준 | [결정] | [이유] |

## AI 자율 판단 범위
- 독립 판단 허용: [목록]
- 반드시 확인 필요: [목록]

## 이 문서에서 파생되는 구현 원칙
[L3 구현 시 반드시 따라야 할 원칙들]
```

### Step 3 — 구현 원칙 확정 후 선언

ONBOARDING.md가 이 프로젝트의 **헌법**이다.
이후 모든 기능 추가/변경 전에 반드시 이 문서를 참조한다.

확정 선언:
```
L0: [확정된 존재 목적]
Never-Do: [확정된 절대 금지 목록]
AI 자율 범위: [확정된 판단 경계]
```
