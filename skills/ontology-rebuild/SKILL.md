# /ontology-rebuild — 피라미드 위상도 전체 재빌드

L0: 모든 산출물이 존재 목적에 연결되도록 구조적으로 강제
L1: 프로젝트 전체 파일·폴더의 L0-L3 위상도를 문서화하여 미래 LLM 세션이 모순 없이 코드를 이해하도록
L2: 폴더별 ONTOLOGY.md + 루트 _WIKI.md 생성/갱신

---

## 이 스킬의 목적

코드에 L0/L1/L2/L3 라벨이 붙어 있어도, LLM 세션이 새로 시작되면 그 연결관계를 모른다.
폴더마다 ONTOLOGY.md를 두어 노드-엣지 위상도를 문서화하면:
- 어떤 파일이 어떤 L레벨에서 작동하는지 즉시 파악 가능
- 의존성 방향이 명확해져 순환 의존·레벨 역전 탐지 가능
- 불변 법칙(invariants)이 각 폴더에 명시되어 미래 수정 시 위반 방지

---

## 실행 절차

### Step 0 — 스캔 대상 결정

인자가 있으면 해당 폴더만, 없으면 현재 프로젝트 전체를 스캔한다.

### Step 1 — 파일별 L-레벨 수집

각 소스 파일의 첫 20줄에서 L0/L1/L2/L3 선언을 추출한다.

**대상 파일**: 바이너리가 아닌 모든 텍스트 파일. 확장자 하드코딩 금지.
파일 첫 8바이트에 `\x00`이 있으면 바이너리로 간주하고 스킵.

처리 단계:
1. 파일 첫 20줄 읽기
2. `L0:`, `L1:`, `L2:`, `L3:` 패턴 탐지 (언어·형식 무관)
3. 선언 있으면 → 내용 추출, 없으면 → "선언 없음" 표시
4. 15줄 미만 파일(trivial)은 스킵

### Step 2 — 의존성 그래프 추출

각 파일에서 내부 import를 추출하여 방향성 의존성 엣지를 구성한다.

**원칙**: 실제 import 구문에서만 추출. 추정·추론 금지.

### Step 3 — 폴더별 ONTOLOGY.md 생성

각 대상 폴더에 대해 아래 템플릿으로 ONTOLOGY.md를 작성한다.

**템플릿:**
```markdown
L0: [이 폴더가 기여하는 프로젝트 L0]

# ONTOLOGY — [폴더 경로]

갱신일: [YYYY-MM-DD]

## 이 폴더의 L-레벨

**주 레벨:** L[N] — [이 폴더가 주로 작동하는 위계 레벨과 이유]

## 파일 위상도

| 파일 | L-레벨 | 역할 | 의존 | 피의존 |
|------|--------|------|------|--------|

## 의존성 방향 (엣지)

[소비자] → [공급자]   # 방향: 소비자가 공급자를 import

## 불변 법칙

1. [이 폴더에서 절대 위반 금지]

## L-레벨 위반 경고

- ⚠ [파일명]: L0 선언 없음 — 추가 필요
```

### Step 4 — 모순 탐지

탐지 대상:
1. **L0 선언 없음**: 15줄 이상인 파일에 L0/L1/L2 선언이 없는 경우
2. **레벨 역전**: L3 파일이 L1 파일을 import하는 경우
3. **순환 의존**: A가 B를 import하고 B가 A를 import하는 경우
4. **매직넘버**: 하드코딩된 숫자에 물리적 근거 주석이 없는 경우
5. **L0 내용 오염**: L0 선언에 기술 세부사항이 포함된 경우

### Step 5 — 루트 _WIKI.md 집계

모든 폴더의 ONTOLOGY.md를 집계하여 프로젝트 루트에 `_WIKI.md` 생성.

### Step 6 — 결과 보고

```
ONTOLOGY REBUILD 완료
─────────────────────
스캔 파일: N개
ONTOLOGY.md 생성/갱신: N개
모순 탐지:
  - L0 선언 없음: N개 파일
  - 순환 의존: N쌍
  - 매직넘버: N개
  - L-레벨 위반: N개

_WIKI.md → [경로]
```

---

## 불변 법칙

1. ONTOLOGY.md는 코드보다 신뢰도가 낮다 — 코드가 바뀌면 이 스킬로 다시 실행해라
2. 선언 없는 파일은 삭제하지 말고 경고만 표시하라 — 판단은 사용자에게
3. 의존성 엣지는 실제 import에서만 추출하라 — 추정 금지
4. 이 스킬이 ONTOLOGY.md를 만들 때도 L0 선언이 첫 줄이어야 한다
