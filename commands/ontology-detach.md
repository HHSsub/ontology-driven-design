# /ontology-detach — 탈존재 원칙 발동 (De-Existence)

L0: 모든 binding에 교체조건이 강제되어 존재집착(고정의 거짓말)을 차단

이 커맨드는 **모든 프로젝트·모든 폴더에서** 호출 가능하다 (글로벌 등록).

## 핵심 법칙

**모든 binding에는 교체조건이 있어야 한다. 없으면 탈존재 위반.**

코드는 끊임없이 "고정"한다 — 값을 변수에, 의존성을 import에, 상태를 파일에, 가정을 하드코딩에, 순서를 절차적 흐름에, ID를 정적 매핑에. 외부 환경(시간, 프로세스, 사용자, API)은 반드시 변하므로 교체조건 없는 모든 고정은 거짓말이 된다.

## 즉시 수행할 것

1. `Skill` 도구로 `ontology-detach` 스킬을 invoke하라 — 6차원 진단·6원칙 설계지침이 적용된다.
2. 현재 작업 대상에 대해 다음 자가질문:
   - 이 binding(값/의존성/상태/가정/ID/순서)의 교체조건은?
   - 답이 "없음"이면 → 탈존재 위반. 다시 설계하거나 교체조건 명시.
3. 인자 있으면 그 파일/폴더 대상 진단. 없으면 현재 작업물 전체.

## 존재집착 6차원 (각 차원에서 "교체조건은?")

1. **상태**: 진실이 영구 저장 → live signal cross-check 후 stale이면 재도출
2. **의존성**: 직접 호출 → 추상 경계(port/adapter)로 격리, 구현 swap 가능
3. **값**: 매직넘버 → 외부 시그널(공식문서·헤더·환경변수·실측) 우선, fallback에 출처 코멘트
4. **가정**: 무검증 "X는 항상 Y" → 경계에서 검증, 위반 시 명시적 실패
5. **식별자**: 같은 개체에 여러 ID → 1:1이면 통합, 다대다면 매핑 함수 명시
6. **순서**: 절차적 흐름 박힘 → 각 단계 idempotent, resume token 재진입

## 탈존재 6원칙

1. 진실은 최신 도출이다, 저장된 사실이 아니다
2. 외부 시그널이 임의값보다 우선
3. 무한 누적은 반드시 차단(cap/rotation/indexing)
4. 라이프사이클 게이트는 정상/예외로 모두 닫는다(try/finally)
5. 분리할 건 분리, 1:1은 통합
6. 단계는 어디서든 다시 시작 가능

## 인자 활용

- `/ontology-detach` → 현재 작업 전체 진단
- `/ontology-detach backend/services/youtube_upload.py` → 단일 파일
- `/ontology-detach 비가역 행동` → 그 카테고리에 집중

## 관련 커맨드

- `/pyramid-ontology` — L0-L3 위계 헌법 (이 스킬의 상위)
- `/pyramid-label` — 파일·코드에 L0~L3 라벨 일괄 적용
- `/pyramid-topology` — 시스템 전체의 위계 토폴로지 점검

## 메타원칙

이 스킬 자체도 탈존재해야 한다. 6차원·6원칙은 현재 분류법일 뿐 영구 진리가 아니다. 새 패턴이 보이면 분류를 갱신하라.
